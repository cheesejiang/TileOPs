# Paged KV cache write on Ascend950

Target environment: Ascend950 / CANN 9.3.0, with a TileLang build exposing
`tilelang.ascend.language` and SIMD FP8 conversion. This revision has **not**
been compiled or timed on that environment. Defaults below are starting points,
not measured winners. The repository's certified toolchain remains unchanged.

The public API remains `PagedKVCacheWriteFwdOp()(k, v, kp, vp, slots, ks, vs)`.
K/V have shape `[N, Hkv, D]`; caches are contiguous `[NP, PS, Hkv, D]`.
Slots are int64 physical row indices, with negative entries skipped. Nonnegative
slots must be unique and less than `NP*PS`. FP8 scales must be positive float32
one-element tensors on the same device. No block table or page allocation is needed.

## Implementation

The optimized kernel loads a contiguous batch of input rows and slots into UB,
then scatters whole rows into the output caches. FP8 batches use SIMD for
FP32 exact division, ordered saturation, round-to-nearest-even conversion,
and explicit signed NaN bytes. No SIMT NaN-repair launch region is needed.
Both K and V are handled by one device kernel. UB buffers are reused only after
the preceding stores; synchronization is generated by the Ascend compiler.

| Workload | Rows per job | Vector cores |
| --- | ---: | ---: |
| llama-8b-decode BF16 | 1 | 64 |
| llama-8b-decode FP16 | 1 | 64 |
| llama-8b-prefill BF16 | 16 | 64 |
| qwen3-235b-fp8 BF16 | 8 | 64 |
| gpt-oss-120b BF16 | 4 | 64 |
| odd-tokens-and-page FP16 | 1 | 7 |
| qwen3-235b-fp8-fp16 | 8 | 64 |

N remains dynamic in the generated program. Other widths and incomplete batches
use the original column-tiled generic kernel; empty calls launch nothing.
The largest default batch uses 64 KiB of K/V data buffers; the FP8 8x512
batch uses 16 KiB of input buffers plus 8 KiB of packed outputs, excluding
alignment, slot and scale buffers. Batched reads include skipped rows, but
stores never touch skipped slots. Very sparse slot masks can favor the generic
kernel, which skips input reads as well.

## Correctness

From the TileOPs directory, in the NPU Python environment:

```bash
PYTHONPATH=src:. python -m pytest -q tests/ops/test_paged_cache_write_ascend.py \
  --tileops-device=npu:3
```

Tests compare every cache byte against a CPU reference, including untouched
rows, for all seven requested shapes. Additional cases cover partial batches,
unaligned/wide rows and empty calls. Separate FP8 tests cover both input dtypes,
signed zero, half-way ties, subnormals, overflow, infinities and signed NaNs.

## Single-card benchmark without clock locking

The seven workloads already exist in the manifest. The new standalone entry
selects one logical NPU before allocating data or compiling kernels. It makes
no clock changes and does not run the shared host-wide reservation checks, so
other cards can remain in use. `--device 3` means logical NPU 3 in the process's
visible device list, which may differ from the physical card ID when visibility
environment variables are set. Keep the selected card free for the measurement.

By default the benchmark checks and measures the optimized Op and the original
generic Ascend kernel, reporting `speedup_vs_generic` for each implementation:

```bash
python scripts/bench_paged_cache_write_ascend.py \
  --device 3 \
  --run-dir /tmp/paged-cache-write-card3
```

Add `--sweep` to compare row batch sizes 1/4/8/16 at up to 32/64 vector cores,
or `--verify-only` to skip timing. `--run-dir` is a directory prefix: each run
automatically appends Shanghai date/time including microseconds, for example
`/tmp/paged-cache-write-card3-20261110-183000-123456`. A numeric suffix handles
timestamp collisions without overwriting earlier runs. The selected directory
is printed at startup. Without `--run-dir`, the prefix is `results/paged-cache-write`.
`--case-regex 'llama-8b-decode'` selects a subset of workloads.

The protocol is `ascend-single-device-unlocked-events-v1`: 3 warmups, 15
individual NPU stream event samples, arithmetic mean latency, and all samples
retained. Private caches are reset, a 1 GiB buffer is zeroed for cache eviction,
and the selected device is synchronized before each event window. These steps
are outside timing. `--warmup`, `--repeats` and `--flush-mb` are configurable;
`--flush-mb 0` measures with no explicit eviction. Events measure stream elapsed
time, which can include host enqueue gaps; these numbers are not interchangeable
with the shared locked profiler protocol. Frequency is left under the runtime's
normal management throughout the run.

`environment.json` records the selected device and software versions,
`results.jsonl` holds correctness results, timings and baseline speedups, and
`result.json` records overall success/failure. `summary.md` summarizes correctness,
mean/median latency in microseconds, speedups against the generic baseline,
the geometric mean speedup of the default implementation, and failure details.
It is updated after each case; interrupted runs retain an in-progress report.
Verify-only runs show no timing or speedup values.
This entry does not require the
shared runner's TileLang 0.1.15 version pin; it still requires the Ascend language
and SIMD APIs used by the kernel. Select defaults from the resulting device
measurements by updating `launch_config`.

The shared `scripts/benchmark_ascend.py` entry remains available with its original
reservation, profiler and clock requirements for other benchmark workflows.

To test another configuration directly, use
`build_batched(width, physical_rows, dtype_string, quantized, rows, cores)`;
N must be divisible by rows, width must be divisible by 64, and
`rows * width <= 16384`. Pass flattened 2D K/V and cache views; FP8 caches
must first be reinterpreted with `.view(torch.uint8)`.
